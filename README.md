# 💬 Asked4Chat (익명 질문 및 1:1 실시간 비밀 채팅 웹 서비스)

> **기존 익명 질문 서비스(Asked)의 단방향 소통 한계를 넘어, 인앱 재화(레터)를 소모해 질문자와 1:1 실시간 익명 채팅을 이어갈 수 있는 양방향 소통 웹 플랫폼입니다.**

---

## 🛠 사용 기술 (Tech Stack)
* **Frontend:** React (Vite), React Router DOM
* **Backend:** Node.js, Express.js
* **Database:** MySQL (Aiven - 정형 데이터), MongoDB (Mongoose - 비정형 채팅/질문 로그)
* **Security & Auth:** JWT (JSON Web Token), bcryptjs
* **Deployment & Env:** Vercel (Frontend), Render (Backend), GitHub Codespaces

---

## 📌 주요 구현 기능

### 1. 회원 인증 및 보안 시스템
* `JWT`와 `bcryptjs`를 활용한 회원가입, 로그인 및 비밀번호 단방향 암호화 처리
* 아이디 중복 확인 API 연동 및 클라이언트 로컬 스토리지 기반 로그인 상태 유지

### 2. 하이브리드 데이터베이스(Polyglot Persistence) 설계 및 연동
* **MySQL:** 유저 정보, 보유 재화(레터) 등 정형 데이터 관리
* **MongoDB:** 질문, 답변, 실시간 채팅 로그 등 빠르게 누적되는 비정형 데이터 처리

### 3. 익명/실명 질문 및 답변(Q&A) 시스템
* 동적 라우팅(`/:username`)을 통해 사용자별 고유 개인 질문방(공개 프로필) 생성
* 화면에는 '익명'으로 표시하되, DB 내부적으로는 실제 발신자(`realSender`)를 매핑하여 추후 1:1 채팅 연결이 가능하도록 데이터 구조 설계
* 대시보드에서 받은 질문 확인, 답변 작성 및 보낸 질문의 채팅방 오픈 상태 조회 기능 구현

### 4. 비즈니스 로직(재화 시스템) 및 1:1 실시간 채팅 구현
* 가상 재화인 '레터(Letter)' 지갑 시스템 구축 (충전 및 리워드 광고 시청 무료 충전 로직)
* 질문 수신자가 1레터를 소모하여 질문자와의 비공개 1:1 채팅방을 개설하는 권한 제어 구현
* 주기적 데이터 폴링(Polling) 방식을 활용하여 채팅방 개설 알림, 실시간 새 메시지 토스트(Toast) 팝업 알림, 안 읽은 메시지 수(Unread Badge) 실시간 동기화 구현

## 🔧 핵심 트러블슈팅 및 UX 개선 경험

### 1. 채팅창 자동 스크롤(Auto-Scroll) 도입을 통한 UX 개선
* **문제:** 채팅 메시지가 누적될 때 사용자가 직접 마우스 스크롤을 내려야만 새 메시지를 확인할 수 있는 사용성 저하 발견
* **해결:** React의 `useRef` 훅을 활용해 채팅창 최하단에 닻(Anchor) 역할을 하는 빈 DOM 요소를 배치하고, 채팅 배열 상태(`chats`)가 업데이트될 때마다 `scrollIntoView({ behavior: 'smooth' })`가 실행되도록 구현하여 매끄러운 채팅 UX 완성

### 2. 로그아웃 후 발생하는 '유령 알림(Ghost State)' 버그 수정
* **문제:** 로그아웃 후에도 상대방이 채팅방을 열거나 메시지를 보낼 때 브라우저에 알림이 계속 뜨는 현상 발견
* **원인 및 해결:** 로그아웃 시 로컬 스토리지의 토큰만 삭제하고 React 내부의 사용자 상태(`myUsername`)를 초기화하지 않아 백그라운드 폴링(`setInterval`)이 계속 동작하던 것이 원인임을 파악. 로그아웃 핸들러 실행 시 사용자 상태, 안 읽은 메시지 맵, 토스트 알림 배열을 모두 초기화하고 폴링을 즉시 중단하도록 조건문을 추가하여 메모리 누수 및 버그 해결

### 3. 클라우드 분리 배포 및 SPA 라우팅 404 에러 해결
* **문제:** 프론트엔드(Vercel)와 백엔드(Render) 분리 배포 후, 메인 페이지가 아닌 특정 유저의 질문방 주소(`/:username`)로 직접 접속하거나 새로고침 시 `404 NOT_FOUND` 에러 발생
* **원인 및 해결:** React가 단일 페이지 애플리케이션(SPA)으로 동작하여 정적 서버인 Vercel이 하위 경로의 물리적 파일을 찾지 못해 발생하는 문제임을 파악. `vercel.json` 설정 파일을 추가하고 모든 경로 요청(`/(.*)`)을 `/index.html`로 리다이렉트(Rewrites)하도록 구성하여 해결
